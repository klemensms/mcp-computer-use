# v0.2.0-beta.1 — Swap helper internals to `BackgroundComputerUseKit`

Replaces the vendored Swift helper (1,549 lines, originally seeded from
`injaneity/pi-computer-use`) with a thin SwiftPM-consumed wrapper around
[`actuallyepic/background-computer-use`](https://github.com/actuallyepic/background-computer-use)
(MIT, © cam + anupam / dubdubdub labs). Helper goes from
self-maintained vendored code to a 620-line wrapper over a battle-tested
upstream library that ships semantic targeting, an AX projected tree, a
verifier, and window motion — all of which we'll surface incrementally
in v0.3.0+.

## What changed

- **Helper internals.** `native/macos/bridge.swift` (deleted) →
  `native/macos/Sources/McpComputerUseHelper/` (5 small files,
  620 lines total). The wrapper imports `BackgroundComputerUseKit`
  and translates our existing JSON-over-stdio wire protocol to upstream's
  Swift API.
- **Build pipeline.** `xcrun swiftc <flags> <source>` →
  `swift build -c release --package-path native/macos`. The build script
  copies the resulting binary to `~/.mcp-computer-use/bridge` as before.
- **Pin.** Upstream is pinned by full SHA in `native/macos/Package.swift`
  (`dcf55a3feee557ebdcda4afa6241c82dc6abdd8c` for this release).
  See [`UPSTREAM_SYNC.md`](../../UPSTREAM_SYNC.md) for the bump ritual.

## What did NOT change

- **MCP tool surface.** All 9 tools (`screenshot`, `click`, `type_text`,
  `key_press`, `scroll`, `wait`, `list_windows`, `get_frontmost_window`,
  `check_permissions`) are byte-identical in shape and behaviour.
- **Wire protocol.** The TS↔helper JSON shape is unchanged.
  `tests/fixtures/mock-helper.mjs` is unmodified and still passes against
  the same `src/native/macos-bridge.ts` it has always passed against.
- **Safety model.** Allowlist, rate limit, secret scan, audit log,
  redaction, PROFILE presets — all TS-side, all untouched.
- **CLI surface.** `mcp-cu-cli` commands and flags are unchanged.

## Breaking changes

These break for anyone installing v0.2 fresh; existing v0.1 installs that
upgrade in place inherit the same requirements going forward.

- **macOS 14+ required.** Upstream's `Package.swift` declares
  `platforms: [.macOS(.v14)]`. We previously had no formal floor (the
  effective floor was macOS 12.3+ for ScreenCaptureKit).
- **Full Xcode required for postinstall build.** `swift build` ships with
  Xcode, not with Xcode Command Line Tools alone. Previously the helper
  compiled with `xcrun swiftc`, which works under CLT-only.
  - Install Xcode from the App Store (or `xcode-select -s /Applications/Xcode.app`
    if it's already installed but unselected).
- **TCC permissions.** Accessibility + Screen Recording grants apply to a
  binary's identity. The helper binary at `~/.mcp-computer-use/bridge` is
  recompiled during the upgrade and may therefore need to be re-granted.
  In practice on Klemens's machine this upgrade kept the existing grants
  intact (granted-by-path persisted across the swap), but YMMV on other
  machines. **If the helper fails permission checks after upgrade**:
  System Settings → Privacy & Security → Accessibility, and again under
  Screen Recording → remove and re-add `~/.mcp-computer-use/bridge`.

## Known limitation (pre-existing, slated for v0.3.0)

- **`list_windows` no-filter mode misattributes pid/bundleId.** When called
  without a `bundleId` filter, all returned windows display under the
  *frontmost app's* pid and bundleId rather than the app each window
  actually belongs to. This is **not** a v0.2 regression — the same
  behaviour exists in v0.1 because neither the old vendored helper nor
  the new wrapper emits per-window `pid`/`bundleId`, and the TS-side
  `mapWindowItem` falls back to a single shared `fallbackApp` value.
  - **Workaround for v0.2:** pass `bundleId` explicitly when you need
    correct attribution, e.g.
    `list_windows({bundleId: "md.obsidian"})`.
  - **Cheap fix for v0.3.0:** emit `pid` + `bundleId` per window in the
    Swift wrapper's `translateWindowDTO`, prefer per-item data in the TS
    `mapWindowItem`. Tracked in
    [`docs/superpowers/plans/2026-04-29-expose-new-capabilities.md`](../superpowers/plans/2026-04-29-expose-new-capabilities.md).

## Upgrade

```bash
# from a clone
git pull
npm install              # postinstall recompiles the helper via swift build
npm run build && npm test
```

For npm consumers, `0.1.0-beta.1` → `0.2.0-beta.1`. No code changes
required client-side.

## v0.3.0 teaser

Now that we're consuming upstream as a SwiftPM library, v0.3.0 is where
the agent-quality wins surface. Tracked work:

- **Semantic targeting** — instead of pixel-coord clicks against
  ScreenCaptureKit pixels, target an AX-resolved element by role + label.
- **AX projected tree exposure** — return upstream's projected tree from
  a `getWindowState`-style MCP tool so an agent can decide *what* to
  click without first doing a screenshot.
- **Verifier classification** — upstream's read-act-read verifier surfaces
  whether an action had the intended effect. Surface this through the
  MCP layer so agents can self-correct.
- **Window motion** — `set_window_frame`, `resize`, drag.
- **`set_value`, `perform_secondary_action`** — additional upstream
  primitives.
- **Per-window `pid`/`bundleId` fix** — the limitation above.
- **Signed `.app` bundle** — eliminates TCC re-prompts on rebuild
  (upstream's `script/bootstrap_signing_identity.sh` solves this).
- **Tagged-release pinning** — once upstream cuts tags, switch from SHA
  pinning to version pinning.

See [`docs/superpowers/plans/2026-04-29-expose-new-capabilities.md`](../superpowers/plans/2026-04-29-expose-new-capabilities.md)
for the v0.3.0 work plan.
